# PostgreSQL later

Moved from CLAUDE.md unchanged (one sentence per line). Keep this note current when the feature changes.

**PostgreSQL later**: the data will be migrated to PostgreSQL, so keep SQL portable.
MySQL-only forms (`LAST_INSERT_ID`, `ON DUPLICATE KEY`, `INSERT IGNORE`, `GROUP_CONCAT`, `YEAR()`, `information_schema` with `DATABASE()`, `IFNULL`, `DATE_FORMAT` and so on) live only in `ph.coop.core.db.Db`, which has helpers for generated keys, upserts, table/column checks and privilege checks; `PortableSqlTest` fails if they appear anywhere else. `LIMIT`, `NOW()`, `CONCAT_WS`, `COALESCE` and `FOR UPDATE` are fine.
Still MySQL-specific: the `V001`-`V010` migration scripts, the pinned MySQL dialect/driver, and mixed-case legacy names (PostgreSQL folds unquoted names to lowercase).
The PostgreSQL branches in `Db` are untested. **The legacy data is already copied into PostgreSQL** (container `eclon-postgres`, port 5440, database `coop`, schema `legacy`; all 380 tables except the 154M-row hourly snapshot, counts checked against MySQL) with keys, indexes and foreign keys being added from `database/postgres/migrations` V006/V007 (finished 2026-10-21: 1,081 indexes and 560 foreign keys; the other 25 MySQL links point at non-unique columns and are listed as comments at the end of V007; 556 of the 560 keys are validated, 4 have old orphan rows: jointacct, coa, coac, wkfcanalysis). `client.Height`, `Weight` and `BloodType` stay in MySQL only (V008 drops them in PostgreSQL, the loader skips them) (generated by `scripts/gen-legacy-indexes.py`); the loader is `scripts/load-legacy-to-postgres.py`; see `documentation/postgres-legacy-load.md` and the `load-legacy-postgres` skill.
The running app still uses MySQL.
